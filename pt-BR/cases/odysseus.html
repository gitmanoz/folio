Runtime agente governado

Odisseus

De workspace de IA a ambiente de engenharia governada

Odisseus é um workspace de IA existente adaptado como primeiro consumidor da Agent Runtime Integration do MOBS. Reutiliza backend, UI e Agent Loop, acrescentando execução e promoção governadas.

Minha contribuição

Conduzo decisões arquiteturais, escopo e revisão da integração MOBS e da experiência de produto. É evolução de uma base existente, sem atribuir a mim a autoria de todas as funcionalidades herdadas.

Estado atual

Fatias implementadas · desenvolvimento contínuo

Uma base útil

Uma base útil

O Desktop Windows empacota backend e UI existentes. Product Shell, tema Graphite, boot workspace-first e propostas intent-first tornam o fluxo de engenharia mais acessível.

Trabalho privado, promoção explícita

Trabalho privado, promoção explícita

Institutional Boot → mandato exato → execução privada → Promotion Artifact selado → autorização → aplicação e verificação.

TEB — workspace privado e fronteira controlada de processos.

Promoção — hashes, preimages e baseline vinculam o candidato à execução.

Autorização — revisão, aprovação de mandato e política operacional permanecem separadas.

Escopo implementado

Escopo implementado

Checkpoints publicados cobrem Controlled Promotion, self-development governado, promoção create/write de exatamente dois arquivos, receitas Python e leitura Git tipada de branch/HEAD/status.

O que ainda está incompleto

O que ainda está incompleto

O Capability Map auditado registra bloqueador físico da TEB Windows e limitações em execução durável, fechamento Git e Computer Use geral. Self-update é futuro. Esses checkpoints não demonstram segurança universal de runtime nem paridade integral com Codex.
